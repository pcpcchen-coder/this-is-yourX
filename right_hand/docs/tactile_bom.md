# 指尖觸覺：採購清單與第一版接法

- 狀態：規劃（2026-10-19）。George 決定下一個元件做觸覺（見 [元件連動規劃](../../docs/12_COMPONENT_INTEGRATION_PLAN.md) §8）。還沒採購，沒有任何實測。
- 目的：讓右手知道自己的指尖碰到了東西。四根手指的指尖各貼一片薄膜壓力感測器（FSR）。
- §1 比較了 FSR 以外的觸覺方案；§2 寫 FSR 的形狀與貼法（含矽膠指套）；§7 估算手能出多少力、結構先壞在哪，給之後的抓握 ADR 用。
- 第一階段**只讀**（A0）：讀值不接進面板、`handd` 或任何控制方法。之後要「碰到就停」時另開 ADR。

## 1. 做法

```
4 × FSR（指尖）─分壓─→ ADS1115（4 通道、16-bit ADC）─I2C─→ Raspberry Pi 4（接著手的主機）
```

- RPi 沒有類比輸入，所以用 ADS1115 讀值。它剛好 4 個通道，一指一個。
- 和伺服機匯流排完全分開：不經過驅動板，也不占序列埠。觸覺壞了不影響手的動作與停止路徑。
- 不用寫韌體，RPi 上用 Python 經 I2C 讀。

### 其他方案（2026-10-19 比較）

不用另外買、可以和 FSR 並用互相比對的：

| 方案 | 量得到什麼 | 限制 |
|---|---|---|
| 伺服機自己的 load 讀值（`present_load`，§7.5） | 馬達出力的估計，8 顆都有 | 分不出「碰到東西」與摩擦、重力；不知道力在指尖哪裡；還沒讀過 |
| 雙目相機看接觸 | 有沒有碰到、軟殼有沒有被壓扁 | 會被擋住、量不到力；只能當輔助證據 |

要另外買的：

| 方案 | 量得到什麼 | 優點 | 缺點 | 定位 |
|---|---|---|---|---|
| **FSR（本文件）** | 有沒有碰到、大概多用力 | 便宜、薄、塞得進指尖；每指 2 條線 | 非線性、漂移、遲滯；類比訊號要靠並聯電阻才分得出斷線（§4） | 第一版 |
| 氣壓感測器包在矽膠裡（BMP280／LPS22 類） | 壓力，線性好 | 比 FSR 準、漂移小；數位 I2C，斷線直接報錯 | 要自己灌矽膠；同型號只有 2 個 I2C 位址，4 指要加多工器（TCA9548A）；每指 4 條線；模組可能比指尖大 | FSR 不夠準時的升級 |
| 磁力式（矽膠裡埋磁鐵 + 三軸磁力計，例如 MLX90393；ReSkin 類） | 三個方向的力，含側向滑動 | 能偵測東西快滑掉，抓握有用 | 伺服機的馬達就在旁邊，磁場可能干擾；製作難度高 | 研究階段 |
| 微動開關 | 碰到／沒碰到 | 最可靠、最簡單，接數位 GPIO | 不知道多用力；要壓到一定的力才觸發 | 可當 FSR 的備援 |
| 壓電片 | 碰撞與振動的瞬間 | 便宜、反應快 | 量不到持續的力 | 搭配用 |
| 近接感測（ToF，例如 VL6180X） | 碰到前的距離 | 快碰到就先減速，對安全抓握有幫助 | 不是觸覺；模組不小；同型號多顆要另接腳位改位址 | 抓握階段再加 |
| 電容觸摸（MPR121 類） | 有沒有被人或導電物碰到 | 便宜，一顆 12 通道 | 對塑膠、木頭沒反應；隔著厚矽膠會變鈍 | 教學時的「摸一下」（選購） |
| 導電泡棉／Velostat 自製 | 壓力 | 最便宜、形狀自由 | 比 FSR 更不穩、更會漂移 | 不採用 |
| 小型 load cell + HX711 | 精確的力 | 準、線性、好校正 | 太大，裝不進指尖；HX711 每秒 10 或 80 筆 | 當校正治具，不裝在手上 |
| 光學觸覺（GelSight、DIGIT 類） | 高解析度的接觸形狀 | 資訊最多 | 太大、太貴，塞不進指尖 | 不採用 |
| 商用觸覺陣列（Paxini、XELA 類） | 多點力分布 | 成品 | 貴，整合工作重 | 抓握研究階段再評估 |

讀法上另一個選項是**小 MCU（XIAO RP2040 類）讀 ADC，再經 USB 送主機**：多一份韌體要維護；之後要把觸覺和硬體看門狗放在同一顆 MCU 上時再考慮。

比較時最重要的三點：

1. **走線**：FSR 每指 2 條線，I2C 感測器每指 4 條，都要穿過兩個會動的關節；線越多越容易斷。
2. **斷線偵測**：數位感測器斷線時直接報錯，自然判定 unknown；類比的 FSR 要靠 §4 那顆並聯電阻。
3. **尺寸**：很多模組比指尖大（§2）。

## 2. 買之前先確認：尺寸、形狀與貼法

### 指尖有多大

官方 CAD 模型裡的遠端指節（最前面那一節），沿主軸量（[`tools/finger_force_estimate.py`](../tools/finger_force_estimate.py) 會印出）：

| 零件 | 長 × 寬 × 厚（約） |
|---|---|
| PLA 硬骨架（`distal`） | 45 × 11 × 10 mm |
| TPU 軟殼（`distal_shell`） | 42 × 21.5 × 21 mm |

Seeed 套件的零件可能和官方模型略有不同，買之前用尺或卡尺量一次。

### 圓形還是長條：用小圓形

外徑約 7–8 mm 的小圓形（Interlink FSR 400 類）：

- FSR 要貼在硬的平面上才準，能當背板的骨架只有約 10–11 mm 寬，7–8 mm 剛好放得下。更大的圓形（FSR 402 類，外徑約 18 mm）會超出骨架，要另外印背板。
- 兩指捏東西時，接觸集中在指腹靠近指尖的一小塊；小圓形加一顆凸點剛好對準，每次讀值比較一致。
- 長條型在這裡吃虧：指節掌側沿長邊不一定是平的，彎曲會造成預壓與漂移，折到會壞；整條只有一個讀值，分不出碰在哪；同樣的力接觸面積不同讀值就不同；尾巴長、走線麻煩。

要偵測「四指包住東西」（接觸在指節中段）時，再在近端指節加一片小圓形，或改用短的長條。第一版不需要。

### 貼在哪裡：兩種做法

位置都是**遠端指節的掌側、靠近指尖**（捏東西時的接觸點）。FSR 的尾巴不要跨過關節：在遠端指節裡就接到軟線，讓軟線去彎。

| | A. 貼在軟殼裡面 | B. 軟殼外面 + 矽膠指套 |
|---|---|---|
| 疊法（由內到外） | PLA 骨架 → FSR → 小凸點 → TPU 軟殼 | TPU 軟殼 → 薄 PLA 硬片（約 0.8 mm、直徑約 10 mm）→ FSR → 小凸點 → 薄矽膠指套（約 1 mm） |
| 背板 | 骨架本身 | 薄硬片（軟殼是軟的，FSR 直接貼在上面讀值會很亂） |
| 要拆軟殼嗎 | 要；先確認軟殼與骨架之間放得下 FSR（約 0.3–0.5 mm）加約 1 mm 的凸點 | 不用 |
| 表面摩擦 | 軟殼原本的 TPU | 矽膠，摩擦更大，捏東西更不會滑 |
| 主要風險 | 軟殼包得緊 → 預壓，基準值變高 | 指套太緊 → 預壓；指套拆裝後位置不同 → 基準值改變 |

不要把 FSR 直接貼在軟殼外面、不加任何覆蓋：FSR 表面是光滑的塑膠，東西更容易滑掉，FSR 也容易被刮壞或撕起來。

### 矽膠指套：只套指尖那一節，不要整隻手套

整隻手套的問題：

1. **手指變難動**：手套跨過關節，手指一彎就要拉伸矽膠。伺服機可持續的扭矩只有約 0.7 kg·cm（§7），多出的阻力容易讓落後檢查誤觸發、電壓下降。官方軟殼一節一節分開，就是為了避免這個問題。
2. **讀值跟著手指角度變**：手指彎曲時手套被拉緊，壓在 FSR 上，沒碰東西也有讀值。
3. **太悶熱**：伺服機在手掌裡，包住會更熱；PLA 約 55–60 °C 開始變軟（§7.3）。
4. **手指變粗**：指與指之間本來就近，容易互碰，造成假接觸與落後。
5. **外觀改變**：相機看到的手不一樣了（§6）。

指套的做法：

- 只包住遠端指節，邊緣離關節留 2–3 mm，不跨過關節。
- 越薄越好（約 1 mm）；太厚會吃掉力，讀值變小又不準。
- 軟殼截面約 21 × 21 mm，差不多是成人的粗手指：買 L／XL 號矽膠指套，或**剪下矽膠或丁腈手套的指尖**（最便宜，大小也容易合）；之後再考慮自己用矽膠翻模。
- 太緊就換大一號或剪短一點。

### 其他要確認的

- [ ] **量實際尺寸**：遠端指節骨架與軟殼的寬、長，和上表比對；選做法 A 的話，拆開看軟殼裡的空間。
- [ ] **走線路徑**：線要從指尖沿著手指走過兩個關節到手掌。手動把手指從張開扳到握拳（伺服機斷電、扭力關），確認沒有地方會夾線或扯線。
- [ ] **RPi 的 GPIO 腳位有空**：要用到 3.3 V、GND、SDA、SCL 四支腳（見 §4）。手的驅動板走 USB，應該沒有占用。
- [ ] **3D 列印**：做法 A 只要小凸點（可以用現成的矽膠膠點）；做法 B 要印 4 片薄硬片（加備品）。自己印還是代印。

## 4. 接線

### 每一指的電路

```
RPi 3.3 V ───────────────┐
                         │          ← 指尖端（FSR 與 1 MΩ 並聯，一起貼在指尖）
                  ┌──────┴──────┐
                  │             │
                 FSR          1 MΩ
                  │             │
                  └──────┬──────┘
                         │          ← 經手指走線、接頭，回到洞洞板
                         ├──────────→ ADS1115 A0（食指）
                         │
                       10 kΩ        ← 放在洞洞板上
                         │
RPi GND ─────────────────┘
```

讀到的電壓 = 3.3 V × 10 kΩ ÷（10 kΩ + FSR 與 1 MΩ 並聯的電阻）。

| 情況 | FSR 的電阻 | 讀到的電壓（約） | 系統應判定 |
|---|---|---:|---|
| 沒碰到 | 很大（近似斷路） | 0.03 V（由 1 MΩ 決定的固定小值） | 無接觸 |
| 輕壓到重壓 | 數十 kΩ → 約 1 kΩ | 數百 mV → 約 3 V | 接觸，力的大小要用秤校正 |
| **任一條線斷了** | — | **0 V**（被 10 kΩ 拉到地） | **unknown**，不是「沒碰到」 |
| 訊號線碰到 3.3 V | — | 約 3.3 V，和極重壓分不太開 | 長時間貼頂、手指又沒在出力時視為 **unknown** |

**為什麼要那顆 1 MΩ：** 沒有它的話，「沒碰到」和「線斷了」讀起來都是 0 V，系統會把斷線當成「沒有接觸」，這是不安全的方向。加上它之後，沒碰到時有一個固定的小讀值，掉到 0 就知道是斷線。這符合「unknown 一律拒絕」的規則（[AGENTS.md](../../AGENTS.md)、[04 §8](../../docs/04_DATA_MODEL_AND_APIS.md)）。1 MΩ 一定要放在**指尖那一端**，放在洞洞板上就偵測不到手指上的斷線。

數值是由元件標稱值推算的，實際以量測為準；量程不合適就換分壓電阻（綜合包）。

### 通道與 RPi 腳位

| ADS1115 | 接到 |
|---|---|
| VDD | RPi 3.3 V（實體腳位 1） |
| GND | RPi GND（實體腳位 6） |
| SDA | RPi GPIO2 / SDA（實體腳位 3） |
| SCL | RPi GPIO3 / SCL（實體腳位 5） |
| ADDR | GND（位址 0x48） |
| A0 | 食指 `hand.right.index` |
| A1 | 中指 `hand.right.middle` |
| A2 | 無名指 `hand.right.ring` |
| A3 | 拇指 `hand.right.thumb` |

注意：

- **ADS1115 的 VDD 只接 3.3 V。** 常見模組的 I2C 上拉電阻接在 VDD 上；接 5 V 會讓 SDA／SCL 變成 5 V，可能燒壞 RPi 的 GPIO。輸入電壓也不能超過 VDD。
- **不要從伺服機的 5 V 變壓器取電。** 觸覺用 RPi 的 3.3 V，和伺服機電源分開（[07 §3](../../docs/07_SAFETY_SECURITY_PRIVACY.md)）。
- 接線、焊接、貼感測器時，**伺服機電源關掉**（延長線開關），扭力關著。

## 5. 到貨後的第一次檢查（只讀）

每一步都不讓手動，結果記在 [`BUILD_LOG.md`](../BUILD_LOG.md)。沒有 experiment ID 的都寫成 bring-up 觀察。

1. **桌上單片測試**（還沒裝到手上）：萬用電表量 FSR 不壓與壓下的電阻，確認每一片都會變。
2. **RPi 看得到 ADS1115**：開啟 I2C（Raspberry Pi OS 用 `raspi-config` → Interface Options → I2C，或在 `/boot/firmware/config.txt` 加 `dtparam=i2c_arm=on`），裝 `i2c-tools` 後 `i2cdetect -y 1` 要看到 `48`。
3. **基準值**：四個通道都不碰，各自讀到約 0.03 V 的固定小值，記下平均與雜訊。
4. **斷線偵測**：拔掉任一指的接頭，那個通道要掉到約 0 V。
5. **對應正確**：一次只壓一根指尖，只有對應的通道變。這同時是「這片是食指的」的第一份證據。
6. **手指動但沒碰東西**：伺服機通電，由人用面板慢慢開合手指，讀值要維持在基準附近。線被彎折、FSR 被拉扯、軟殼或指套拉緊造成的假讀值會在這一步現形；套了指套之後這一步最重要。
7. **（做法 B）重複穿脫**：指套拆裝 3 次，每次記基準值，比較差多少。差太多就要固定得更牢，或每次裝好都重新校正。
8. **校正**：每根指尖壓在電子秤上至少 3 個力量點（例如約 20、100、300 g），記下讀值與克數。FSR 有遲滯，每點加壓、放開各記一次。
9. **更新率**：量每個通道實際每秒幾筆（ADS1115 規格上限是全部通道合計 860 筆／秒）。

## 6. 之後要補的（還沒做）

照根目錄 [AGENTS.md](../../AGENTS.md) 的「Hardware adapter」與「Component/schema change」規則：

- ADR：觸覺的定位（只讀、之後怎麼接進停止條件）。
- 觸覺 adapter：真的（ADS1115）和假的各一份。每筆讀值帶 timestamp、quality、freshness；斷線、讀值卡住、I2C 錯誤都回報 unknown；附 safe-state 測試。
- manifest：四個指尖感測元件，例如 `hand.right.index.tip_force`（`kind: sensor`；`ownership` 是 `intrinsic` 還是 `attached` 在 ADR 裡定），更新 `right_hand/config/body.yaml` 與驗證測試。
- 版本紀錄：FSR、指套都會改變手的外觀與接觸特性，對自我模型是一次元件變更，要記 hardware revision。相機校正與視覺資料要在決定好貼法之後才開始收；之前的相關證據標成失效（[05](../../docs/05_EXPERIMENTS_AND_ACCEPTANCE.md) 的 E07）。
- 驗證之後才考慮的：「碰到就停」只能讓系統更保守，要改面板的檢查，需另開 ADR。抓握也是另一份 ADR，起始上限的提議見 §7.4。

## 7. 手能出多少力、結構先壞在哪（估算，給之後的抓握 ADR）

2026-10-19 依 George 的問題整理。**全部是估算，沒有實測**；FSR 裝好後第一件事就是用電子秤量實際指尖力，取代這一節的數字。

### 7.1 為什麼現在不能抓握

不是馬達沒力，是軟體刻意擋下來的。一次移動切成很多小步，每步檢查每顆伺服機有沒有落後目標超過 12°／15°／19°（慢／中／快），走完沒在 8° 內到位也算失敗；任一項成立就關扭力並鎖住 fault（`LAG_EXCEEDED`、`NOT_SETTLED`，見 [`hand_api/motion.py`](../hand_api/motion.py)）。手指碰到物體停住、目標還往前走，正好觸發這個檢查。

這是有意的：沒有力或電流回授，ADR-0006／0007／0008 都把抓握排除在外，[面板文件](hand_panel.md) 也寫「不要用它抓握」。硬體本身可以施力：SCS0009 是位置伺服，被擋住時會持續出力想走到目標，目標設得越深入物體力越大，直到伺服機的上限。

### 7.2 指尖力

方法：從官方 MuJoCo 模型取出「伺服機轉一點，指尖走多遠」，再用兩顆伺服機的扭矩換算成指尖沿運動方向能出的力（虛功法）。腳本是 [`tools/finger_force_estimate.py`](../tools/finger_force_estimate.py)。

```bash
pip install mujoco numpy      # 不在 requirements.txt 裡
git clone https://github.com/pollen-robotics/AmazingHand
python right_hand/tools/finger_force_estimate.py AmazingHand/Demo/AHSimulation/AHSimulation/AH_Right/mjcf/scene.xml
```

2026-10-19 在開發環境跑的結果（官方 repo commit `3e82410`，MuJoCo 3.16.0）：

| 手指彎曲 | 指尖每 rad 走 | 堵轉時的指尖力（只能撐幾秒） | 額定扭矩下的指尖力（可持續） |
|---:|---:|---:|---:|
| −30°（張開） | 105 mm | 3.5 N | 1.3 N |
| 0° | 87 mm | 4.2 N | 1.6 N |
| 30° | 64 mm | 5.8 N | 2.1 N |
| 45° | 52 mm | 7.2 N | 2.6 N |
| 60° | 39 mm | 9.6 N | 3.6 N |
| 75° | 23 mm | 16 N | 5.9 N |
| 85°（快握到底） | 11 mm | 33 N | 12 N |

用的扭矩：堵轉 1.89 kg·cm（Seeed 標示 5 V 下的值，和 6 V 堵轉 2.3 kg·cm 按電壓換算相符）、額定 0.7 kg·cm（6 V 規格）。1 N 約是 100 g 的重量。

怎麼讀：

- 一般握持範圍（0–60°）：可持續約 1.5–3.5 N（150–350 g 重），短時間最多約 4–10 N。
- **快握到底時，同樣的扭矩被機構放大好幾倍。** 這是結構受力最大的位置；落後檢查看的是伺服機角度，同樣落後幾度才停，停下之前在指尖出的力也跟著被放大。
- 實際會比表上小：面板平常讀到的電壓是 4.6–4.7 V，比規格的 5–6 V 低；摩擦、軟殼變形、伺服機效率都沒算。
- 能拿多重：拇指與食指捏、TPU 軟殼摩擦係數取 0.5–1，能穩定拿約 100–300 g。四指包住整個物體可以更多；官方 Overview 寫「Up to 1Kg payload」，沒寫測試條件。

### 7.3 結構與系統先壞在哪（依風險排序）

| 風險 | 位置 | 原因 |
|---|---|---|
| 最高 | 舵盤 | 舵盤半徑約 5 mm，堵轉時每支連桿約受 37 N 以上，接近握到底時更大。這股力全在自己鑽孔、M2 自攻的舵盤上；[BUILD_LOG](../BUILD_LOG.md) 記過 2 顆的孔靠近耳朵邊緣、孔壁較薄 |
| 高 | 球頭連桿 | 塑膠座包住的 M2 球頭，受力大時可能脫出 |
| 高 | 發熱 | PLA 大約 55–60 °C 開始變軟，面板的伺服機溫度上限是 60 °C，已在軟化範圍；長時間受力時 PLA 會慢慢變形（潛變） |
| 中 | 電源 | 規格表寫每顆伺服機堵轉約 1 A（6 V）。四指全力堵轉需要的電流遠超過變壓器的 3 A，兩指全力就碰到上限；快速檔出現過的 `VOLTAGE_SAG` 是同一類問題 |
| 中 | 螺絲與螺帽 | 印件上的自攻螺絲、連桿上的 M2 螺帽受力後會鬆；組裝手冊要求連桿螺帽鬆了就點膠 |
| 較低 | PLA 本體 | 官方列印建議：手指硬件 PLA、層高 0.2 mm、填充至少 80%；軟殼 Filaflex 82A。在伺服機出得了的力內，短時間通常撐得住；比較怕層與層之間被拉開與受熱 |

**外力比自己出的力更危險**：減速比很高（規格寫 1:416），手指被撞、被人用力扳時，力直接進齒輪與舵盤。

官方 README 的 Disclaimer：這個設計還沒做過長時間或複雜的抓取測試，安全抓握之前要先做一層控制。

### 7.4 第一版抓握的建議上限（提議，還沒決定）

抓握要另開 ADR，而且等觸覺第一次檢查（§5）通過之後才做。做法不是放寬或關掉落後檢查，而是一個專門的模式：慢速合攏 → FSR 偵測到接觸就停 → 再往內多走有上限的一小段 → 握住時監看指尖力、溫度、電壓與時間 → 任何異常或時間到就放開。接觸之後的落後是預期的，其他檢查都留著。

建議的起始上限：

| 項目 | 上限 |
|---|---|
| 指尖力 | 2–3 N（FSR 實測後再調） |
| 伺服機溫度 | 45–50 °C（不用面板現在的 60 °C） |
| 握住時間 | 10–20 秒，時間到就放開讓伺服機降溫 |
| 手指 | 先只用兩指捏（拇指 + 食指），不要四指同時全力 |
| 彎曲角度 | 不要讓手指為了抓東西深壓到快握到底的角度 |
| 物體 | 先用 100 g 以內、不怕壓的東西：海綿、泡棉球、紙杯 |

開始之前，先檢查那兩顆孔壁較薄的舵盤，有疑慮就換備品。

### 7.5 伺服機自己的 load 讀值與過載保護（還沒讀過）

rustypot 1.11.0 的 `Scs0009PyController` 有這些方法（2026-10-19 在開發環境列出方法名稱，沒有接實體伺服機）：

- `read_present_load`：馬達出力的估計值，不是真正的力。可以當 FSR 之外不用花錢的第二個來源，例如捏住東西時 load 有沒有跟著上升。
- 過載保護相關：`protective_torque`、`protection_time`、`overload_torque`、`max_torque_limit`、`unloading_condition`（各有 read／write）。看名稱是「過載超過一段時間後由伺服機自己降低出力」，不靠主機。

這些值目前的設定、單位與實際行為都還沒查，也沒在實機上讀過。下一步可以寫一支**只讀**工具，讀 8 顆的 load 與保護設定；再在扭力開著、手指停住時由人用手輕推，看 load 會不會跟著變。要寫入保護設定之前，先查清楚它存在 EEPROM 還是 RAM（EEPROM 不適合頻繁寫入），並另開 ADR。

來源：[Pollen Robotics AmazingHand](https://github.com/pollen-robotics/AmazingHand)（README Disclaimer、`docs/AmazingHand_3DprintingTips.pdf`、`docs/AmazingHand_Overview.pdf`、MuJoCo 模型；Apache 2.0，模型不收在本 repo）；SCS0009 規格：[Pakronics](https://www.pakronics.com.au/products/feetech-scs0009-ultra-compact-servo-6v-2-3kg-for-amazing-hand-ss100067882)、[Hubtronics](https://hubtronics.in/feetech/sc-0090-c001)、[OpenELAB（Seeed）](https://openelab.com/products/seeed-studio-feetech-scs0009-ultra)。各家對額定扭矩與齒輪材質的寫法不一致，以上取保守的數字。

## 8. 限制

- FSR 不是精密的力感測器：讀值和力不是直線關係，會漂移、有遲滯，每片之間也有差異。可以用來判斷「有沒有碰到、大概多用力」，不能當精確的力量測。
- 只量得到垂直壓在感測面上的力，側面的接觸量不到。
- 指尖以外的地方（指腹、手掌）碰到東西量不到。
