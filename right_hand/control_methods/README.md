# control_methods — 控制這隻右手的方法

操作者用不同的輸入裝置控制右手的方法，一種方法一個資料夾。

| 資料夾 | 輸入 | 做什麼 | 狀態 |
|---|---|---|---|
| [`qring_fist/`](qring_fist/README.md) | QRing R08 智慧戒指的三軸加速度（藍牙，接在 Mac 上） | 操作者握拳，手跟著握拳；張開，跟著張開 | 2026-10-11 已實作並安裝；實機上有 bring-up 觀察，沒有 experiment ID。[ADR-0008](../../docs/adr/0008-qring-fist-operator-control.md)（proposed） |
| （規劃中） | 雙目相機（[`stereo_camera/`](../../stereo_camera/README.md)） | George 打算之後用它做另一種控制方法 | 還沒開始；做法未定 |

右手原本就有的兩條路不在這個資料夾裡：人在瀏覽器上逐指操作的[網頁操作面板](../docs/hand_panel.md)（`hand_panel/`），
以及 AI 提議已校正手勢、操作者逐次核准的 [`hand_api`](../docs/hand_api_design.md)。

## 放進這裡的方法要守的界線

這些是 `qring_fist/` 採用、之後的方法也應該沿用的做法；理由在 ADR-0008。

- **給人用，不是 AI 的控制路徑。** 輸入到手指角度是決定性的換算，裡面沒有生成式模型。AI 發起的動作仍然只走 `hand_api` 的
  skill gateway（[ADR-0006](../../docs/adr/0006-hand-skill-api-mcp.md)、根目錄 [`AGENTS.md`](../../AGENTS.md)）。
- **不自己碰伺服機匯流排。** 經由網頁操作面板的 HTTP 介面，以「一個控制的頁面」的身分操作：啟用扭力、下目標、停止。
  落後、電壓、溫度、掉線、到位、閒置、心跳的檢查與 fault 鎖定留在面板那一側，不重做也不繞過。
- **啟動要人明確動作；輸入不可信時不動。** 程式啟動、裝置連上、校正完成都不會讓手動。輸入無效、過期或超出校正範圍時不送新目標。
- **輸入裝置斷線、程式結束就關扭力；** 面板關了扭力（閒置、fault、別人按停止）就跟著停，不自己再啟動。
- 面板的位址、主機名稱與個人校正資料不進 Git。
- 實機上的觀察照實寫：誰操作的、依據是哪一份紀錄、有沒有 experiment ID。
