# qring_fist — 用戒指握拳控制右手（QRing Hand 0.2.0）

操作者戴著 QRing R08 智慧戒指握拳，Amazing Hand 右手跟著握拳；張開，它跟著張開。
0.2.0 新增左右側擺作為獨立的戒指輸入；四姿勢校正、側擺讀值與可調中立範圍見 [側擺輸入說明](sway-input.md)。機器手的動作對應仍是握拳。

這是 [`control_methods/`](../README.md) 底下的第一種控制方法。決策見 [ADR-0008](../../../docs/adr/0008-qring-fist-operator-control.md)（proposed）。

macOS App（Apple Silicon）「QRing Hand」。戒指用藍牙接在 Mac 上；手接在 Raspberry Pi 上，經由
[網頁操作面板](../../docs/hand_panel.md)（`right_hand/hand_panel`）的 HTTP 介面控制。面板與 `hand_api` 都沒有改。

## 1. 這是什麼、不是什麼

- 是給「人」用的遙控工具，和網頁操作面板同一類：操作者本人戴著戒指、看著手、搆得到伺服機電源開關。
- **不是 AI 的控制路徑，裡面沒有任何模型。** 戒指讀值到手指角度是固定的幾何換算（[`follow.py`](follow.py)）。
  AI 發起的動作仍然只走 `hand_api` 的 skill gateway（[ADR-0006](../../../docs/adr/0006-hand-skill-api-mcp.md)）。
  這個 App 的本機服務（只聽 127.0.0.1）和面板的 HTTP 介面一樣接受會讓手動起來的請求，不得接到任何模型或 agent 上。
- 不做抓握、接觸物體、個別手指、手勢辨識、左手。

## 2. 怎麼運作

```
操作者的手 ─戒指三軸（藍牙）→ QRing Hand（Mac）─HTTP（區域網路）→ hand_panel（接著手的主機）→ 8 × SCS0009
              重力方向          校正模型 → 握拳程度 0–100%          落後／電壓／溫度／心跳／閒置保護
```

1. 戒指的加速度計在手不晃動時量到的是重力方向。手掌方向不變時，握拳會讓戴戒指的那節手指繞指根轉一個角度，
   重力方向在戒指座標裡沿著一條弧線移動。
2. 校正記下「張開」與「握拳」兩個方向。之後把目前的方向投影到這條弧線上，得到握拳程度。
3. 握拳程度換成四根手指的彎曲角度：張開（彎曲 −30°、側擺 0°）到握拳姿勢之間線性內插。握拳姿勢預設是內建的四指彎曲 85°，
   也可以選面板上存好的姿勢（例如 `stone`）。結果收在面板的限制內（彎曲 −30°–90°、側擺 ±40°、兩顆伺服機各 ±90°）。
4. App 在面板眼中是一個「控制的頁面」：`GET /api/status?client=…`（每 0.25 秒，同時是心跳）、`POST /api/enable`、
   `/api/fingers`（最多每 0.12 秒一次，和面板頁面拖滑桿時相同）、`/api/stop`、`/api/clear_fault`、`GET /api/poses`。
   落後、電壓、溫度、掉線、到位、閒置、心跳的檢查與 fault 鎖定都在面板那一側，這裡不重做也不繞過。

戒指的藍牙協定（三軸快照、觸控事件、電量、觸控設定的備份與還原）沿用戒指 repo
[pcpcchen-coder/qringr08plus](https://github.com/pcpcchen-coder/qringr08plus) 的 `mac-app/` 已在這顆戒指上驗證過的部分；
這個 App 不啟動任何光學量測，也不改戒指的內建排程。

## 3. 安裝

需要 macOS（Apple Silicon）、Xcode 或 Command Line Tools（Apple 的 Python 3.9、`swiftc`、`codesign`）。

在 Finder 對 [`install.command`](install.command) 按兩下，或在終端機：

```bash
zsh right_hand/control_methods/qring_fist/install.command
```

它會：結束執行中的 QRing Hand（先請內建服務正常收尾：關扭力、還原戒指設定）→（第一次）用 `/usr/bin/python3` 建 `.venv` 並安裝
[`requirements.txt`](requirements.txt) → 跑測試 → 建置 → 封裝自我檢查 → 複製到 `~/Applications/QRing Hand.app` → 開啟。紀錄留在 `build-install.log`。已經有裝好相依套件的 Apple Python 3.9 venv
（例如戒指 repo 的 `.venv`）時，可以用 `QRING_HAND_PYTHON=<那個 venv 的 python> zsh install.command` 沿用。

面板的位址不寫進 Git。要讓 App 一裝好就知道位址，建置前照 [`site.example.json`](site.example.json) 放一份 `site.json`；
不放也可以，之後在 App 的「設定」填。

第一次開啟時 macOS 會問兩個權限，都要允許：**藍牙**（連接戒指）、**區域網路**（連接面板）。
這是本機 ad-hoc 簽章的開發版，沒有經過 Apple 公證。每次重新建置簽章都會變，macOS 會再問一次藍牙權限；在允許之前按「連接戒指」
會得到 `Bluetooth device is turned off`，允許之後再按一次就好（0.1.0 換 0.1.1 時遇到過）。權限一直對不上時，先完整結束 App 再重開，
必要時在系統設定移除舊的 QRing Hand 項目後重新允許。

## 4. 使用

開始之前：伺服機的 5 V 變壓器接在有開關的延長線上，一隻手搆得到開關；手的活動範圍內沒有東西。
接著手的主機上面板要開著（`systemctl --user status hand-panel`）。

1. **連接戒指**：戴好戒指，讓手機的 QRing App 斷線；QRing Studio 若連著這顆戒指，先在那邊中斷。按「連接戒指」。
2. **連接手掌**：在「設定」填面板位址（例如 `192.168.1.50:8765`）後按「連接」。之後開 App 會自動連（只讀狀態）。
3. **校正**：到「校正」按「開始校正」。手掌擺成平常要操作的方向，張開停住約 2 秒，顯示「已停穩」後按「記錄張開」
   （或單擊戒指）；握拳停住，按「記錄握拳」。張握幾次看握拳程度有沒有跟上，再「儲存校正」。
4. **啟動**：回到「控制」，按「啟動跟隨」，再按一次確認。手會立刻走到你現在的握拳程度，之後跟著動。
5. **停止**：按開關、右上角的紅色「停止」、鍵盤 Esc、選單列的「停止」，或長按戒指。扭力會關掉。

關閉視窗只是隱藏，App 留在選單列；從選單列「結束 QRing Hand」或 ⌘Q 才會結束（結束時關扭力、還原戒指的觸控設定）。

### 校正的訣竅與限制

單顆三軸加速度計只量得到重力方向，所以：

- 原兩點模式校正和操作時，手掌要維持同一個方向。0.2.0 四點模式可加入左右側傾，見 [限制與校正](sway-input.md#能觀測的自由度)。
- 手掌直立、手指朝前（握手的姿勢）量不到：握拳的轉軸和重力平行，讀值不變。兩個姿勢相差不到 20° 時校正會被拒絕。
- 轉手腕或前臂也會改變讀值，戒指分不出動作來源。兩點模式離開校正弧線超過「方向偏離容許」時保持舊目標；四點模式改採已校正的左右範圍。
- 揮動手臂時量到的不只是重力；大小不在 0.8–1.2 g 的取樣不採用。
- 一顆戒指只有一個握拳程度，四根手指一起動。

## 5. 什麼情況會停下來

啟動前的條件（任何一項不成立都不啟用扭力，開關下方會寫原因）：戒指已連線、已校正、面板連得到而且沒有 fault、匯流排是 attached、
8 顆伺服機都有回應、沒有別的頁面在控制、選的握拳姿勢在面板上可重現、握拳讀值是 1 秒內而且有效的。

| 情況 | 結果 |
|---|---|
| 戒指斷線 | App 對面板送關扭力，回到停止 |
| 讀值無效（手在晃、方向偏離、超出範圍）或戒指資料中斷 | 不送新目標，手停在上一個位置（扭力仍開著，之後由面板的閒置逾時關掉） |
| 手停著沒有新目標超過面板的閒置時間（預設 60 秒） | 面板自己關扭力；App 跟著停，不會自己再啟動 |
| 面板的檢查沒過（落後、電壓、掉線、過溫、沒到位） | 面板關扭力並鎖住 fault；App 停止。人看過之後在「手掌」按「解除鎖定」 |
| 有人在面板頁面按停止，或另一個頁面接手 | App 停止 |
| 連不到面板 | App 停止並補送一次關扭力；面板 3 秒沒收到心跳也會自己關 |
| App 結束、視窗程序當掉、收到 SIGTERM | 內建服務收尾時關扭力、還原戒指設定 |
| 內建服務本身當掉、Mac 當機或斷網 | 靠面板的 3 秒心跳看門狗 |

紅色「停止」經過 Mac、網路與面板程式，**不是 E-stop**；伺服機電源上的實體開關才是。面板被強制結束、主機當掉時的行為和
[`hand_panel.md`](../../docs/hand_panel.md) §5 寫的相同。

「長按戒指啟動」預設關閉：戒指握著東西也可能被當成長按，手會在操作者沒看著的時候動起來。「跟隨中長按：停止」與「校正時單擊：記錄／儲存」預設開。

## 6. 設定

| 項目 | 預設 | 說明 |
|---|---|---|
| 移動速度 | 中 | 面板的 `slow`／`normal`／`fast` |
| 握拳姿勢 | 內建（四指彎曲 85°） | 可以改選面板上可重現的姿勢當作握到底的樣子 |
| 握拳幅度 | 100% | 握到底時走到握拳姿勢的幾成 |
| 跟隨的手指 | 四指 | 沒勾選的留在張開位置 |
| 模式 | 連續 | 連續：握多少跟多少；兩段：只有張開與握拳（60% 以上握、40% 以下開） |
| 平滑 | 50% | 指數平滑；越高越穩、越慢 |
| 張開／握拳到底的界線 | 12%／88% | 兩端留餘裕，不必每次都和校正時一模一樣 |
| 最小變化 | 4% | 小於這個變化不送，避免抖動 |
| 方向偏離容許 | 35° | 超過就停在上一個位置 |
| 戒指觸控 | 開 | 需要時開啟戒指的觸控回報，結束時還原原設定 |

### 快照輪詢調校（0.1.2 起）

戒指沒有已驗證的串流模式，三軸是「送一次 `A1 03`、收一筆」的快照輪詢。三個時間和 QRing Studio 0.4.0 同名同義，都可設 0–2 秒，
按「套用並儲存」後下一輪生效，跟隨中也可以改：

| 介面 | 設定鍵 | 預設 | 意義 |
|---|---|---|---|
| 快照發送節拍 | `accel_period` | 0.1 秒 | 每兩輪開始之間的最短間隔；0 盡快進下一輪 |
| 等待新取樣上限 | `accel_timeout` | 0 秒 | 送出後最多等新取樣多久；0 不等 |
| 取樣或逾時後休息 | `accel_interval` | 0 秒 | 收到取樣或等到上限後再休息多久；0 不休息 |

一輪的長度 ≥ max(節拍, 寫入＋實際等待＋休息)；每輪只有一個寫入，落後節拍時不補送；三個都設 0 時仍會讓出事件迴圈。
連續 1 秒沒收到任何回報時，一輪自動拉長到 0.5 秒（Studio 沒有這一條；這裡保留 0.1.1 的行為，避免戒指不回時寫入一直堆著）。

| 預設按鈕 | 節拍 | 等待上限 | 休息 | 說明 |
|---|---|---|---|---|
| 10 Hz 固定（預設） | 0.1 | 0 | 0 | 0.1.1 的固定節拍；實機上看過 8.5–14.7 Hz |
| 20 Hz 節拍 | 0.05 | 0.03 | 0 | 同 Studio 的 20 Hz 預設 |
| 等回報（0.1.0） | 0 | 0.3 | 0.06 | 0.1.0 的做法；實機上約 4 Hz |
| Studio 原設定 | 0 | 0.35 | 0.15 | Studio 0.3.0 以前的流程 |
| 最快測試 | 0 | 0 | 0 | 只用來測上限 |

面板上顯示最近 2 秒的實際送出、收到三軸、數值變化（次／秒），以及累計數、等待逾時、平均等待、最後取樣年齡與最大間隔；
套用新設定、重新開始輪詢、按「重置統計」都會歸零。協定沒有要求編號，這些是到達統計，不是感測器的原生取樣率，等待逾時也不是掉包率。
輪詢只在跟隨、校正或 App 畫面開著時進行。節拍或休息設到 1 秒以上時，「啟動跟隨」要的「1 秒內的有效讀值」可能不成立，畫面會提醒。
0.1.1 存的「三軸讀取：等回報」第一次開 0.1.2 時會換成「等回報（0.1.0）」那三個值。

個人資料在 `~/Library/Application Support/QRing Hand/`：`calibration.json`（校正）、`preferences.json`（設定，含面板位址）、
`session-*.jsonl`（每次執行的事件紀錄；不含三軸原始資料）。都不進 Git。面板那一側的動作另外記在它自己的 `panel_events.jsonl`，
呼叫者是 `operator.web:ringhand…`。

## 7. 和其他工具的關係

- **面板頁面**：可以同時開著看狀態、按停止。扭力由誰啟用，誰就是控制者；另一邊只能看和停止。
- **`finger_cal.sh`、`handd --adapter scs`**：QRing Hand 連著面板時，面板佔著匯流排，這些工具會回報被占用。在 App 按「中斷手掌」，6 秒後面板放開。
- **QRing Studio**（戒指 repo 的 App）：兩個 App 不要同時連同一顆戒指。QRing Hand 連線前會問本機的 QRing Studio 是否連著戒指，是的話拒絕連線。

| `test_hand.py` | 69 項測試 |
| `site.example.json` | 這台機器的預設面板位址範例；實際的 `site.json` 不進 Git |

```bash
cd right_hand/control_methods/qring_fist
.venv/bin/python -m unittest -v test_hand.py          # 模擬戒指＋模擬面板，約一分鐘；只需要 aiohttp，不需要 macOS
```

示範模式要連模擬的手：`bash right_hand/tools/hand_panel.sh --http-port 8766`（預設是模擬 adapter），再把面板位址填成那一個埠。
