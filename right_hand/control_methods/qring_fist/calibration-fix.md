# 0.3.1：左右側擺校正失敗的調查與修正

日期：2026-10-14（Asia/Taipei）。操作者回報左右側擺一直失敗，錯誤為「請保持手指張開／側擺角度需在 10–65°」。

## 查明的問題與證據範圍

0.3.0 的 `PalmModel` 同時檢查 `abs(latitude) <= 65°` 與 `abs(along) <= 15°`，只要任一失敗就顯示同一則訊息。後者是**側擺沿握拳方向的伴隨偏移**，不是側擺大小。自然側傾若伴隨超過 15° 的偏移，即使側擺本身在範圍內，也會被拒絕。UI 沒有顯示該條件。

流程也有問題：左側取樣先標成「已記錄」，到右側完成才一起驗證兩側；之前的失敗未寫入事件紀錄。最近的校正流程能看到張開、握拳、左側記錄後取消，無法從舊紀錄回溯每次到底是哪個條件失敗。因此確認的是程式的限制與誤導訊息，不能宣稱每次實際失敗都是 15° 所造成。

目前戒指連線正常。先前單一快取取樣曾顯示高加速度；重新取得新取樣後約 1 g 且可停穩，不能把那筆快取當成持續的感測器故障。

## 修正

- 取消側擺必須接近握拳平面垂直方向的 15° 限制。由左右各自的取樣，記下側擺角度 `side_end` 與伴隨偏移 `along_end`。
- 側擺比例仍由緯度計算，握拳座標改為 `theta_corrected = theta_raw - (latitude / side_end) * along_end`。左右各自補償、不要求幅度或偏移對稱；跨 atan2 的 ±180° 時選擇靠近有效握拳弧線的分支。
- 保留可辨識側擺 10–65°。兩方向分離度 `atan2(abs(latitude),abs(along))` 至少 20°，沿握拳偏移最多 80°；太小、太大、難以分開、左右同側分別顯示實際數值與修正方法。這些界線避免不可辨識的雙輸入，不等於完整手腕姿態追蹤。
- 每一側在記錄當下驗證。失敗只清除本次姿勢，保留其他已記錄姿勢，可以重試，不必重做張開與握拳。
- 校正頁即時顯示可辨識側擺角度、沿握拳偏移、方向分離度、可記錄／拒絕原因。錯誤持續保留在校正訊息，並寫入本機 `calibration_rejected` 事件；不再只短暫顯示提示。校正加速度大小不合格時也會顯示 g 值與 0.9–1.1 g 的條件。

補償仍是依個人校正方向的近似模型。實體手掌複合動作是否符合線性補償、方向與手感，都需由操作者試用，不能從合成方向測試推定。

## 校正遷移與使用

0.3.1 新做的四姿勢校正存為 **version 3**，含左右角度、伴隨偏移與分離度診斷。舊 version 2 校正仍可讀回，保持不補償的舊映射，既有檔案不自動覆寫；version 1 的啟動限制不變。

**請重新做張開 → 握拳 → 左側擺 → 右側擺校正，再儲存，才能使用新的補償。** 側擺時手指保持自然張開，不必刻意讓另一個方向完全不變。若顯示超過 65°，減少側傾；若顯示不足 10° 或分離度太小，改變中立方向或側傾方式。平行桌面的左右旋轉仍可能量不到。

降回 0.3.0 時，舊版不認識 version 3，需還原備份的 version 2 或重做校正。App、個人設定與校正的備份保留本機 `.build.noindex/`。機器手目標限位、啟動確認、停止、斷線與面板保護均保留。
